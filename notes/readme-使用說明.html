這個 Vault 怎麼用

筆記更新 2026-08-03·整理狀態：未標示

其他名稱 2

README · 使用說明

一句話

五個固定角度保存知識，MOC/ 負責導航。同一角度維持固定結構；手術只是 Intervention 的 subtype，不另開 Surgery 知識庫。

詞彙定義看 CONTEXT；為什麼這樣設計看 docs/adr/。

五個角度

資料夾 放什麼 這個角度回答的問題
Disease/ 有診斷名稱的病理狀態（syndrome 也放這） 這個病是什麼、怎麼診斷、怎麼治
Workup/ 尚未診斷的主訴流程 值班遇到這個主訴，下一步做什麼
Test/ PE、抽血、影像、病理 這個檢查在測什麼、怎麼判讀
Drug/ 藥品與藥理分類 機轉、適應症、要注意什麼
Intervention/ 手術、透析、插管、引流 什麼時候做、怎麼做、會有什麼併發症

MOC/ 不在上表，因為它不是第六個角度；它只把不同資料夾裡的專篇串成科別入口。外科輪訓從 Surgery Rotation 進入。

Test 和 Intervention 的分界是「意圖」

為了取得資訊 → Test。為了改變病人狀態 → Intervention。 診斷性腹腔穿刺是 Test，治療性腹水引流是 Intervention。同一個技術動作，各寫一篇並互連。

外科怎麼放

  • 疾病與手術門檻 → Disease/
  • 影像、病理、定位與分期 → Test/
  • 手術 → Intervention/，使用 Operation 手術 模板
  • 術後症狀或偏離的分流 → Workup/
  • 停藥、預防、止痛與免疫抑制 → Drug/
  • 一個 service 的總入口 → MOC/
不建立平行的 `Surgery/` 知識庫

例如 CAD 只有一篇 Disease；Cardio 與 CardiacSurgery 透過 services: 與各自的 MOC 觀看同一篇。不要再複製「內科版 CAD」與「外科版 CAD」。

最重要的一條：Case 是來源，不是內容

案例可能來自考古題、case discussion、晨會、或你真正照顧過的病人。不管哪一種，case 都只是觸發學習的事件。

從 case 學到的東西要用通用臨床語言寫進五個角度的筆記；case 本身只記在 source: 欄位。

✗ 不要寫 ✓ 改成
「考古說上腹痛要開 EKG」 「上腹痛必開 EKG 排除下壁 MI」
「本題答案是膿胸」 （刪掉——換個 case 答案就不同）
「這是評分表的給分點」 「這是知情同意的底線」
「B06 B 組記載病人兩週前感冒」 「近期呼吸道感染是 parapneumonic effusion 的關鍵病史」
判準只有一句

這句話換一個來源還成立嗎？ 不成立就不該寫進筆記。

圖的尺寸紀律

Obsidian 不會自動縮放 Mermaid——太寬會被切掉、太高會一眼看不完。

項目 上限
節點總數 約 14 個
分類樹層數 3 層（主訴 → 系統 → 疾病群）
單行字數 約 14 個中文字（用 <br/> 換行）
末梢處理 同一系統下的疾病合併成 1 個節點，用 ・ 隔開
  • 分類樹 → flowchart LR：寬度＝層數，好控制；高度＝分支數，可捲動。
  • 機制／流程 → flowchart TD：LR 會愈接愈寬而被截斷；TD 只會變高，捲動即可。

開一篇新筆記

  1. 在對應資料夾建立新檔案，檔名 = 最常用的英文名或縮寫（DLBCL、Gout、Chest pain）
  2. Cmd + P → Insert template → 選對應角度；正式手術選 Operation 手術，科別入口選 MOC 科別索引
  3. 補 aliases：中文名 + 英文全名 + 其他縮寫。之後你打「痛風」也連得到 [[Gout]]
  4. 新筆記使用 Clinical/<Angle>/... tag；既有 Med/... 是 legacy，不需為了改名立即批次遷移
  5. 補 services:：列出會實際使用這篇的團隊，例如 Cardio、CardiacSurgery；跨科時列多個，不複製筆記

完成度：status 三級

不要求一次寫完。用 status 標清楚哪些信得過：

status 意思 必須有
骨架 只有模板，還沒填 —
可用 值班時信得過，而且讀得完 一句話總覽 + 頂部行動卡 + 禁忌區塊（沒有就明寫「無」）+ 下方三條密度標準
完整 全部節都填了 上述 + 所有節
目標是先讓每篇都到「可用」

一篇「可用」大約 5–10 分鐘。20 篇可用的筆記，價值遠高於 3 篇完整加 17 個空檔。

「可用」的密度標準

「可用」不只是「有寫」，是值班時查得到、考前讀得完。寫太多跟沒寫一樣沒用——因為你不會去讀。

一、資訊型態決定呈現方式

這種內容 用這個 不要用
可列舉、彼此平行（分型、藥物、鑑別診斷、禁忌） 表格 攤成散文——會失去掃描性
有因果或推導（機制、「一句話推出整張清單」、反直覺的點） callout 塞進表格——因果會被切碎
銜接與定位（這一節在講什麼、兩個概念的關係） 兩三句話的段落 條列——邏輯會斷掉

判準：這段是「一堆並列的東西」還是「一條推理」？ 並列用表，推理用 callout，其餘才用段落。整篇都是散文跟整篇都是表格一樣難讀。

二、刪不刪，只問兩句話

值班時我會翻回來查嗎？考古題考過這件事嗎？ 兩個都不是 → 刪。

依這把尺，這四類幾乎一定要刪：

該刪 留什麼
完整診斷準則的逐條表（Framingham criteria、Duke criteria 的每一項） 一句話說明它存在、判定門檻、以及現在還算不算數
評分系統的計分細節（H₂FPEF 哪一項幾分） 評分名稱 ＋ 它由哪幾類因子組成
效應量數字與世代研究名（HR 4.7、Framingham／WHI／LIFE） 方向——哪個是危險因子、往哪邊偏
指引建議等級的細分（Class 2a vs 2b、ESC 與 AHA 的下界差 20 ms） 最強適應症 ＋ 一句「缺條件就降一級」

三、三種東西再長也不刪

  1. 反直覺的點——推不出來、只能記的。低血鈉在心衰竭是壞事；心搏過緩對 HFpEF 反而是保護；甲狀腺低下不是高輸出量心衰竭。
  2. 絕對不可 四欄表——這是禁忌系統的資料來源。
  3. 頂部行動卡——值班時只看得到這一格。

四、寫法

  • 專有名詞用英文，縮寫首次出現時給全稱：left ventricular ejection fraction (LVEF)、mineralocorticoid receptor antagonist (MRA)。之後直接用縮寫。
  • 篇幅參考值：一篇 Disease 約 300 行以內。超過就回頭套第二把尺。

空的節怎麼辦

直接不寫。模板不編號就是為了這件事——刪掉一節不會讓後面跳號，heading 連結（[[AML#診斷]]）也不會斷。

連結怎麼寫：短清單原則

跨角度連結寫在 frontmatter 的具名欄位裡（treated_by、indication…），不散在內文。但只寫在清單短的那一端。

這個清單 短嗎 寫不寫
洗腎的適應症（AEIOU，5 條） 短 寫在 Intervention/Dialysis
胸痛的鑑別診斷 短 寫在 Workup/Chest pain
高血鉀的治療 短 寫在 Disease/Hyperkalemia
哪些疾病要驗 CBC 無上限 不寫，靠 backlinks

反查（「誰連了我」）用右側 Backlinks 面板。日後若要自動化，裝 Dataview 即可直接查詢這些欄位，不用回頭改筆記——見 docs/adr/0001。

內文連結兩條規則

規則一：連什麼

這個詞會不會有自己的一篇筆記？會 → 連。不會 → 用粗體。

連 不連（用粗體）
疾病名、檢查名、藥名、處置名（＝五個角度的實體） PE 手法（Murphy's sign）、症狀描述（板狀腹）、指標（pH、LDH）、解剖名詞、口訣（Charcot 三徵）

規則二：連幾次

每個 H2 章節第一次出現時連，同章節內第二次起用純文字。

理由：連結是為了「跳過去」，不是為了「標記提到過」。全篇只連一次的話，你讀到「鑑別診斷」看到 EKG 想點，得往回捲到最上面；每次都連則會洗版 backlinks 面板。以章節為單位剛好平衡。

重複連結對 Graph 沒有影響

官方文件：「Lines represent internal links between two nodes」「The more nodes that reference a given node, the bigger it gets」。 所以同一篇裡連 5 次 [[EKG]] 仍然只有一條線，節點也不會變大——節點大小取決於有幾篇筆記連它。 真正的代價只在 Backlinks 面板：那裡會逐一列出每次出現的上下文片段。

Graph 的雜訊用設定解決：Filters → Existing files only 打開，就不會顯示還沒寫的筆記。

最容易犯的錯：反引號會殺掉連結

`[[EKG]]` ← 反引號 = 程式碼，連結失效 [[EKG]] 寫成 [[EKG]]（不加反引號）才是真連結。 模板裡的空槽 [[]] 是刻意留白，填入名稱即生效。

圖示

圖檔一律放 vault 根目錄的 assets/，用 ![[assets/檔名.png]] 嵌入。

流程：模板在該配圖的位置已經留好統一標記——

> [!todo] 📷 要插入圖片｜{什麼圖}
> **要能看到**：{判讀重點}

寫筆記時先把「要能看到」填掉（這行決定你之後挑圖時能不能一眼判斷合不合用），之後找到圖再把整個 callout 換成 ![[assets/檔名.png]]。

找待補的圖：全域搜尋 要插入圖片 就是你的配圖待辦清單。

版權

教科書與 UpToDate 的圖有版權。個人筆記自用屬灰色地帶，但優先用明確可用的來源： Wikimedia Commons → NCBI Bookshelf / StatPearls → Radiopaedia。存進來時在圖下註明出處。

Mermaid 架構圖：Obsidian 內建支援，不需外掛。Workup 的「鑑別架構圖」用 flowchart LR，致命分支上紅色 class。 注意：Mermaid 節點裡放不了 wikilink——圖負責看全貌，表格負責點進去。

深度歸屬：同一件事只寫一次

UPCR 的原理只寫在 Test/UPCR。Disease/DM 只寫「要驗 UPCR」與判讀結論，不重抄原理。

否則三個月後你有五份版本不一的說明，而且不知道哪份才對。

禁忌

每個模板倒數第二節固定是 ## 禁忌與陷阱，裡面是四欄表：

情境 │ 絕對不可 │ 為什麼 │ 該做什麼

同時在 tags 加 禁忌，就會自動出現在 禁忌選項。考前讀那一頁。
